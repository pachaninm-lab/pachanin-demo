# Тела запросов, замеренные и признанные не требующими DTO

Ратчет `verify-request-validation-coverage.mjs` считает **объявления**, а не достижимость и не фактическую проверку входа. Поэтому в его счётчике остаются обработчики, у которых вход проверяется другим способом — иногда единственно возможным. Ниже перечислены такие случаи: что замерено, почему DTO там не нужен, и как перепроверить.

Смысл этого списка — не оправдание, а защита от косметики. Добавить DTO в любой из них легко, счётчик уменьшится, а никакого дефекта закрыто не будет. Хуже: в двух случаях DTO сломал бы работающую защиту.

## `ai-insights/restricted-public-qwen.controller.ts` — 2 тела

`@Body() body: unknown` **обязателен**, а не небрежность.

```ts
verifyInternalSignature(body, headers);
verifyPublicSourceBoundary(body);
```

Подпись считается по телу в том виде, в каком оно пришло. Глобальный `ValidationPipe` работает с `transform: true`, то есть DTO-преобразование пересобрало бы объект — и подпись перестала бы сходиться. DTO здесь не добавил бы проверку, а **отключил бы имеющуюся**: единственную, которая отличает вызов из своего контура от чужого.

Проверка входа выполняется, и она строже DTO: неподписанный вызов получает 401 и не узнаёт формы контура — потоковый обработчик отвечает статусом, а не кадрами на 200.

## `gekta/gekta-anonymous-admission.controller.ts` — 1 тело

Вход уже проверяется поимённо и закрыто:

```ts
if (!deliveryAuthorized(deliveryKey)) throw new ForbiddenException(...);  // timingSafeEqual
const sid = String(body?.sid || '').trim();
const ticket = String(body?.ticket || '').trim();
if (!SESSION_ID_PATTERN.test(sid) || !freshTicket(ticket)) throw new BadRequestException(...);
```

`String(...)` снимает вопрос типа, шаблон `^[A-Za-z0-9_-]{20,32}$` — формы, `freshTicket` — срока годности билета, `timingSafeEqual` — ключа доставки. DTO повторил бы то же самое вторым способом.

## `storage/storage.controller.ts` — 2 тела

Оба обработчика разбирают вход через отказывающие закрыто помощники сервиса:

* `confirmUpload` → `normalizeSha256` — `^[a-f0-9]{64}$`, иначе `INVALID_SHA256`; сравнение хэша идёт через `timingSafeStringEqual`;
* `requestUpload` → `requiredIdentifier(dealId)`, `sanitizeFilename(filename)`, `assertAllowedMime(mimeType)`, `assertAllowedSize(sizeBytes)`.

Каждый из них — уже проверка входа, а не приведение типа.

## `logistics/logistics.controller.ts` — 1 тело

Маршрут инертен: `logistics.transition` имеет тип возврата `never` и выбрасывает `GoneException` через `canonicalCommandRequired`. Тело не читается. DTO на маршруте, который не выполняется, — определение фиктивного исправления.

## Как перепроверить

```bash
node scripts/security/verify-request-validation-coverage.mjs
```

Счётчик по этим файлам остаётся ненулевым намеренно. Если в любом из них появится обработчик, который действительно читает непроверенное тело, он попадёт в тот же счётчик и его будет видно — список не создаёт исключений в инструменте и ничего не скрывает.

## Чего этот список НЕ утверждает

Он не утверждает, что перечисленные модули безопасны. Он утверждает ровно одно: конкретные тела запросов в них замерены, и добавление DTO не закрыло бы ни одного найденного дефекта, а в двух случаях сняло бы работающую защиту.
