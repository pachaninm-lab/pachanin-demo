## Официальный внешний контракт

### Transport

Официальный интеграционный формат — SOAP 1.1, XML/XSD и асинхронная бизнес-очередь. WSDL содержит только три транспортные операции:

- `SendRequest` (`urn:SendRequest`);
- `SendResponse` (`urn:SendResponse`);
- `Ack` (`urn:Ack`).

HTTP-ответ `accepted` означает постановку сообщения в очередь, а не успешное завершение бизнес-операции. Полученный результат необходимо сначала атомарно сохранить в PostgreSQL, и только затем отправлять `Ack`: после ACK сообщение удаляется из внешней очереди.

MTOM/XOP является подтверждённым способом передачи вложений. REST paths `/lots`, `/shipment`, `/acceptance`, `/certificate` не присутствуют в официальном контракте.

Официальные источники:

- [страница API оператора](https://specagro.ru/fgis/api);
- pinned package 1.0.23 из `fgis-grain-api-1.0.23.source-lock.json`;
- package SHA-256 `085e22c50b6564219585c96e814b0793d906f4c5e401cbb7446a949c26f0bcd7`.

### Чтение партий

Каноническая операция — `RequestGetListLot` / `ResponseGetListLot` (`GET_LIST_LOT`). Для delta sync подтверждено поле `recordsModifiedFrom`; pagination использует `Paging` и `hasMore`, максимум 100 записей для несервисных справочников.

`RecordLotType` подтверждает следующие данные:

- внешний `id` и номер партии — хранить раздельно;
- owner, agent, repository;
- crop с ОКПД2 и опциональным ТН ВЭД;
- target, purpose, harvest year, storage place;
- показатели качества как код + строковое значение;
- status;
- `amountOriginal`, `amountAvailable`;
- `dateRegistration`, `lastModified`;
- признаки organic product и quarantine zone.

Важные запреты mapping:

- `sourceUpdatedAt` берётся из `lastModified`, а `fetchedAt` создаётся платформой;
- отдельного поля `sourceVersion` в записи нет — это версия адаптера;
- generic списка связанных документов в `RecordLotType` нет;
- отдельного доказанного source для каждого quality value нет;
- поля единицы измерения в `RecordLotType` нет: выдумывать `unit` нельзя;
- расхождение нумерации страниц 0/1 требует preprod conformance-теста.

Статусы партии контракта: `SUBSCRIBED`, `CANCELED`, `BLOCKED`, `IN_ARCHIVE`.

### Чтение СДИЗ

Для P0.2 разрешён read-only `RequestGetListSDIZ` / `ResponseGetListSDIZ`. Создание, подписание, аннулирование или погашение СДИЗ остаётся отдельным юридически значимым контуром исполнения Сделки. Транспортная подпись системы не даёт TAI, staff или платформе право подписывать СДИЗ вместо клиента.

### Подпись

Контракт требует `InformationSystemSignature`; сертификат определяет систему-инициатора. Пакет указывает ГОСТ Р 34.11-2012/256, ГОСТ Р 34.10-2012/256, Exclusive C14N и СМЭВ-transform.

Обнаружен конфликт документации: XSD требует `XMLDSigSignatureType`, а текст пакета одновременно упоминает PKCS#7 1.5. Production PASS запрещён до успешного preprod conformance или официального разъяснения.

## Доказанные P0 `UNSAFE` пути

1. `packages/integration-sdk/src/live/live-fgis-zerno.adapter.ts` — вымышленный REST и `VENDOR MAPPING`, хотя официальный transport SOAP.
2. `POST /integrations/fgis-zerno/deals/:dealId/push` вызывает mock registry, отправляет hardcoded wheat/100 и возвращает `MOCK_OK`.
3. Активный `SagaModule` вызывает mock adapter для register/shipment/acceptance/certificate; staff-роли могут инициировать действия вместо продавца/подписанта.
4. `POST /integrations/fgis/webhook` и `POST /api/webhooks/fgis` используют вымышленный JSON/HMAC callback вместо signed SOAP, durable inbox и ACK. Один допускает отсутствие timestamp и хранит idempotency только в памяти.
5. `apps/api/src/modules/admin/admin.controller.ts` объявляет FGIS saga step `live`, что противоречит `NOT_ATTESTED` и disabled transport.
6. `auction.register_verified_lot` принимает `sourceType/sourceExternalId` от клиента и сам выставляет `source_verified_at=now`, `status=BIDDING`, `admission_status=ADMITTED` без snapshot, refresh, reservation и source FK.
7. `apps/api/src/modules/lots/*` и `apps/web/app/api/lots/route.ts` создают/публикуют in-memory/demo lots без PostgreSQL reservation, object authorization и concurrency authority.

Первый implementation PR после этого аудита должен только fail-close/quarantine эти пути. Он не должен добавлять новый адаптер, модели или UI.

## Отсутствующий канонический домен

Не найдены сущности или эквивалентные PostgreSQL authorities:

- seller lifecycle для `FgisConnection`;
- immutable `FgisPartySnapshot`;
- `FgisPartyCurrent`;
- `FgisSyncRun`;
- `CommodityReservation` ledger;
- persistent `LotPassport`;
- `FgisReconciliationCase`;
- atomic command публикации подтверждённого лота.

Требуемая команда публикации должна выполняться в одной `SERIALIZABLE` PostgreSQL transaction под trusted tenant context:

1. object-level authorization;
2. lock `party_current`;
3. freshness and critical-state validation;
4. available-volume recalculation;
5. active reservation;
6. immutable lot passport bound to the source snapshot;
7. auction lot bound by FK to passport and reservation;
8. audit and outbox;
9. commit or full rollback.

## Точные внешние блокеры

Не требуется абстрактное «обращение в ФГИС». Для live binding отсутствуют конкретные сведения и доказательства:

1. точные SOAP URL production и нового preprod; WSDL всех опубликованных версий содержит только `http://localhost/api/ws/{version}`;
2. API version, реально включённая на каждом URL;
3. регистрация information-system initiator и привязка его X.509 certificate reference;
4. доказанная связь инициатора с ИНН/КПП/ОГРН продавца и его data scope;
5. operator-accepted signed `SendRequest` и `Ack`, разрешающие XMLDSig/PKCS#7 conflict;
6. подтверждение, нужны ли дополнительно mTLS, IP allowlist или иные network credentials.

mTLS, IP whitelist, OAuth, bearer token, `client_secret` и API login/password сейчас имеют статус `UNKNOWN`, а не `REQUIRED`. ЕСИА относится к пользовательскому ЛК; логин/пароль ЕСИА не должны передаваться платформе как API credentials.
