# Финальный пакет: что осталось подписать

Всё, что можно было выполнить машинно, аналитически и документарно, выполнено и лежит в репозитории. Ниже — исчерпывающий перечень действий, которые юридически невозможно совершить без конкретного физического лица. Их **четыре**, и они закрывают всё оставшееся.

Каждая позиция даёт: что подписать, кем, готовый документ, какие файлы и коммиты он закрывает, какой показатель после подписи становится PASS.

## Текущее состояние показателей

```
PASS  THIRD_PARTY_PRODUCT_CODE=0
PASS  UNKNOWN_PRODUCT_CODE=0
PASS  UNRESOLVED_LICENSES=0
OPEN  UNRESOLVED_FIRST_PARTY_PROVENANCE=133
```

Открыт один показатель. Кодом он не закрывается — только подписью. Что после подписи он действительно закрывается, проверено пробой: с внесённой записью об исполненном документе гейт выдаёт `ALL_KPI_PASS`, без неё — снова открытый показатель.

### Какой из двух документов подписывать

Выбор определяется фактическими отношениями, а не удобством. Подписывать нужно **один**.

| Как фактически выполнялась работа | Документ | Основание |
|---|---|---|
| В рамках трудового договора, в пределах трудовых обязанностей | `04-employee-work-confirmation-platon.md` | ст. 1295 ГК РФ — служебное произведение; исключительное право у работодателя изначально |
| По договору подряда/заказа или вне трудовых отношений | `02-assignment-agreement-platon.md` + `03-acceptance-act-platon.md` | ст. 1234, 1285, 1288 ГК РФ — отчуждение исключительного права |

Косвенный признак в пользу второго варианта: git-адрес — локальное имя личной машины (`MacBook-Pro-Platon.local`), корпоративного домена в истории нет. Это не доказательство; решает фактическая природа отношений, которую знает правообладатель.

### После подписания — одно действие

Внести запись в `docs/ip/legal/executed-instruments.json`:

```json
{
  "schemaVersion": "pc-crop.executed-instruments.v1",
  "instruments": [
    {
      "contributor": "Platon",
      "instrument": "docs/ip/legal/02-assignment-agreement-platon.md",
      "status": "EXECUTED",
      "signedAt": "2026-__-__",
      "appendix": "docs/ip/legal/appendix-platon-covered-works.md"
    }
  ]
}
```

Затем `node scripts/ip/verify-first-party-provenance.mjs` — должно выйти `ALL_KPI_PASS`.

## Чего в этом пакете нет и почему

**Ф.И.О., ИНН, ОГРН, адреса, паспортные данные.** Их нет в репозитории, и вносить их в репозиторий не следует. Они проставляются при подписании — это единственные пропуски в документах, и они намеренные.

**Размер пошлины.** Не проставлен, чтобы не зафиксировать устаревшую величину; проверяется на дату подачи.

**Подписи.** Ни одна не имитирована и ни одна не заменена вторым аккаунтом.

## Как перепроверить всё самостоятельно

```bash
node scripts/ip/verify-contributor-identity-register.mjs
node scripts/ip/verify-legal-instrument-consistency.mjs
node scripts/ip/build-first-party-provenance.mjs
node scripts/ip/verify-first-party-provenance.mjs
node scripts/ip/build-ip-due-diligence.mjs
```

Каждая команда отказывает при расхождении и называет расхождение. Ни один показатель не выставляется вручную.

Счётчики учётных записей инструментов растут с каждым коммитом — в том числе с тем, который нёс бы исправление, — поэтому проверка реестра по умолчанию сравнивает направленно: каждая видимая учётная запись обязана быть классифицирована, и вклад неоформленного человека не может вырасти. Точное равенство проверяется отдельно, сразу после пересборки: `node scripts/ip/verify-contributor-identity-register.mjs --write && node scripts/ip/verify-contributor-identity-register.mjs --strict`.

**Замечание о состоянии дерева.** Приложение с перечнем произведений собирается по состоянию, непосредственно предшествующему коммиту, в котором оно лежит, — иначе оно ссылалось бы на собственный хэш до его существования. Документы приведены к тому же состоянию, и это соответствие проверяется машинно. Перед подписанием приложение имеет смысл пересобрать на актуальном состоянии — оно и документы обновятся вместе:

```bash
node scripts/ip/build-contributor-assignment-appendix.mjs
node scripts/ip/verify-legal-instrument-consistency.mjs --write
```
