# Удаление истории и повторный перенос Гекты

Запрос удаления конкретного диалога и запрос очистки истории относятся только
к аккаунту текущей подтверждённой сессии. После успешного ответа строки
диалогов физически удалены из основного PostgreSQL. Существующий внешний ключ
каскадно удаляет сообщения, текст, цитаты и метаданные вложений. Очистка
захватывает также ранее скрытые строки с `deletedAt`. Удаление проекта
по-прежнему возвращает его диалоги в общую историю.

Миграция не стирает историю при выпуске. Удаление выполняется только по
явному запросу пользователя. Ограниченный runtime-принципал получает право
исполнить одну функцию очистки, но не прямое DELETE таблиц. Функция использует
фиксированный search_path, ограничивает удаление accountId/ID и блокирует
существующую строку аккаунта. Импорт и создание диалогов используют ту же
блокировку; запись в уже удалённый диалог не восстанавливает его.

Для переноса браузер отправляет стабильный локальный sourceId. Квитанция и
вложенные сообщения сохраняются атомарно. Одноимённые и одинаковые диалоги с
разными sourceId остаются разными. Повтор того же ID и содержимого не создаёт
вторую строку; изменённый повтор получает конфликт без изменений в базе.
Квитанция переживает удаление, чтобы старая вкладка не восстановила историю.
Стабильный импорт атомарно сохраняет также отпечаток для старого клиента без
sourceId. Перед удалением он дополняется для ранее записанных диалогов,
включая диалоги, у которых уже была только стабильная квитанция. Дедупликация
старого клиента не объединяет разные стабильные ID с одинаковым содержимым.

Квитанция содержит только accountId, технические importKey/conversationId,
дату и SHA-256 отпечаток запроса с отдельным purpose и accountId. Текст, заголовок, цитаты,
вложения, телефон, email и пароль в ней не сохраняются. Квитанции хранятся
до удаления аккаунта. Отпечатки не зависят от AUTH_TOKEN_PEPPER: смена ключа
аутентификации не разрешает повторно импортировать удалённые сообщения.
Хеш — технический идентификатор для дедупликации, не шифрование и не гарантия
конфиденциальности: при доступе к квитанции можно проверять догадки о содержимом.
Доступ к ним ограничен существующей серверной границей аккаунта и правами базы.

У старых клиентов без sourceId возможна только совместимость по содержимому:
их одинаковые заголовки, локаль и набор сообщений считаются одним переносом;
порядок и даты не являются идентификатором. Старый импортированный диалог без
квитанции принимается только при совпадении его фактического содержимого.
Перед удалением такого диалога сохраняется минимальный SHA-256 отпечаток для
защиты от его повторного переноса. Новый клиент использует стабильные ID.

Эта операция доказывает удаление строк основной базы, а не перезапись диска,
WAL или уничтожение защищённых резервных копий. Сроки и восстановление копий
подчиняются существующей отдельной процедуре; факт их физического стирания
данным API не объявляется. Отдельное хранилище файлов не создаётся.

Приёмка должна исполнить настоящий PostgreSQL-тест с ограниченным
принципалом, отдельными соединениями, конкурентным дублем, различными
одноимёнными диалогами, импортом против очистки, устаревшим append против
удаления, сохранением чужого аккаунта, отказом прямого DELETE и полным откатом
вложенной ошибки. Локальные адаптеры и prisma validate этого результата не
подменяют. Выпуск, новые runtime-ревизии и живые пользовательские действия
остаются отдельной приёмкой.
