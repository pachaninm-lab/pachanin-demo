Статус: **BLOCKED_EXTERNAL_PREREQUISITES / NOT CERTIFIED / NOT PRODUCTION**

Собранного `.cfe`, лицензированного runtime run, демонстрационной базы, production credential, production traffic или официальной заявки нет.

## Что подготовлено внутри репозитория

- машиночитаемый readiness manifest с отрицательными фактами и внешними решениями;
- матрица 54 требований: общая часть, два возможных категорийных маршрута и условия подачи;
- шаблон состава submission package без вымышленных target/applicant значений;
- полное руководство пользователя как blocked template;
- протокол 25 изолированных acceptance cases;
- синтетический семикомандный demo plan без реальных данных и реквизитов;
- финальный текст уточнений для SV-1097 со строгим запретом отправки;
- deterministic verifier и Jest contract с проверкой обнаружения tamper;
- source-controlled scope под lock `PC-CROP-FEDERAL-ACCOUNTING`.

Эти материалы закрывают всё, что можно честно сделать без выбора точной конфигурации, лицензированного стенда, юридических сведений заявителя и ответа 1С. Они не являются сертификационным пакетом и не дают права использовать логотип.

## Официальные требования, положенные в основу

Матрица построена по опубликованным 1С [требованиям к программным продуктам](https://1c.ru/rus/products/1c/predpr/compat/soft/requirements.htm), [условиям проведения сертификации](https://1c.ru/rus/products/1c/predpr/compat/soft/condition.htm) и [странице подачи заявки](https://sovmestimo.1c.ru/cert/). Для оформления исходников и безопасного транспорта учтены стандарты 1С по [текстам модулей](https://its.1c.ru/db/content/v8std/src/400/100/i8100456.htm), [описанию процедур и функций](https://its.1c.ru/db/content/v8std/src/400/100/i8100453.htm), [HTTPS](https://its.1c.ru/db/content/v8std/src/600/i8100669.htm) и [безопасному хранению](https://its.1c.ru/db/content/v8std/src/600/i8100740.htm).

Общая часть требований обязательна. По архитектуре применимыми кандидатами остаются раздел 7 для продукта обмена данными и раздел 8 для расширения конфигурации. Официальная заявка допускает одну категорию, поэтому категория не выбирается без ответа 1С. Если применяется раздел 8, необходимы точный текущий релиз конфигурации, назначение «Адаптация» или «Дополнение», зарегистрированный префикс, совпадающие свойства расширения, инструкция по установке/обновлению/отключению/удалению/смене релиза, решение по БСП, защищённому хранению, профилю безопасности и unsafe mode, readme/release notes и демонстрационная база с подключённым расширением.

## Внешние решения, которые нельзя подменить кодом

| Решение | Кто подтверждает | Почему блокирует |
| --- | --- | --- |
| Категория и одна/две заявки | 1С в SV-1097 | Определяет применимый раздел и форму пакета |
| Точная конфигурация, редакция, релиз и платформа | 1С | Без них нельзя строить metadata, profile и acceptance |
| Назначение расширения, имя, префикс, каталог | 1С | Требуется для объектов, API, свойств и поставки |
| Профиль безопасности, unsafe mode, БСП/хранилище | 1С | Определяет допустимый runtime security contract |
| Маршрут demo stand и submission package | 1С | Нельзя отправлять базу или пакет произвольным способом |
| Лицензированный toolchain и exact target | Владелец | Нужны законная сборка `.cfe` и фактические тесты |
| Юридические сведения, поддержка, гарантии, подпись/печать | Владелец | Это действия и гарантии заявителя |

## Последовательность после получения решений

1. Зафиксировать ответы 1С в source-controlled decision record; выбрать ровно одну категорию на заявку.
2. Под законной лицензией получить точную конфигурацию, платформу и build/check toolchain без нового обязательного расхода либо запросить отдельное разрешение на расход.
3. Зарегистрировать идентичность и сформировать target-specific EDT/XML metadata. Применить префикс ко всем собственным объектам, методам и переменным; завершить русскоязычную документацию экспортного API и форматирование.
4. Реализовать только один compatibility profile для подтверждённого релиза. Generic RPC, динамический dispatch, SQL и прямой DB-доступ остаются запрещены.
5. Собрать воспроизводимый `.cfe`, записать toolchain/provenance и SHA-256, сформировать readme и release notes.
6. Создать отдельную синтетическую demo DB, выполнить 25 cases, сохранить redacted evidence и устранить только доказанные failures.
7. Заполнить руководство, applicant/legal fields и официальный пакет; провести финальный integrity check.
8. Показать владельцу точный текст SV-1097 и отправить только после команды «Отправляй»; дальнейшие материалы передавать лишь по подтверждённому маршруту.
9. Подать пакет, пройти официальные проверки и только после положительного результата обновить статус. Production остаётся отдельным этапом с отдельной авторизацией.
