## Что предлагается

**Wave 2, первый срез: signing authority.**

Не весь Wave 2 (документы, договоры, regulatory — это 7% веса), а его наименьший
осмысленный кусок, который замыкает дыру, оставленную Wave 1.

### Почему именно он

Wave 1 сознательно оставил `documents.sign` недостижимым: ни профиль, ни делегирование
её не выдают, БД отказывается хранить её в делегировании. Это правильный отказ по умолчанию,
но он оставляет систему без способа подписать вообще. Раздел 29 контракта требует
`SigningAuthority` с `mchd_reference`, сроками, лимитом суммы, разрешёнными типами документов
и отпечатком сертификата.

Пока этой сущности нет, любой следующий wave, который дойдёт до подписи, будет вынужден
либо ослабить инвариант Wave 1, либо остановиться. Замкнуть контур дешевле сейчас.

### Существующая основа

`UkepCertificate` (`schema.prisma`) уже хранит сертификат. Это `EXTEND`, а не `CREATE`:
добавляется authority-слой поверх сертификата, а не второе хранилище сертификатов.

## Инварианты

1. Приватный ключ платформой не хранится (§29). Модель хранит только ссылки и отпечаток.
2. Подпись разрешается только при одновременном выполнении: активный membership,
   совпадение tenant/org, документ актуален, свежая MFA, authority действительна,
   МЧД действительна где применимо, тип документа и сумма в пределах, сертификат разрешён.
3. `documents.sign` по-прежнему не выдаётся профилем и не делегируется. Wave 1 не ослабляется:
   capability остаётся необходимым, но недостаточным условием, а не заменой authority.
4. Expand-only миграция. `UkepCertificate` не переносится и не переименовывается.
5. Отзыв authority немедленно закрывает подпись, без ожидания истечения срока.
6. Deny-by-default: отсутствие authority = отказ, а не «разрешено по умолчанию».

## Приёмка

- Каждое из условий §2 проверяется отдельным negative-тестом, включая просроченную МЧД,
  превышение лимита суммы, неразрешённый тип документа, чужой tenant и отозванный сертификат.
- Подпись документа, устаревшего после пересчёта веса/качества/цены, отклоняется (`STALE`, §15).
- Отзыв authority проверяется как немедленный.
- Полный API unit-suite без регрессий; forward-only gate проходит.

## Чего этот срез не делает

Не подключает провайдера подписи, не выпускает КЭП, не трогает UI и не создаёт
production-доказательств. Это серверный контур авторизации подписи, не сама подпись.

## Зависимости

Внешних нет. Vendor-договоры не требуются. Новых обязательных расходов: 0 ₽.
